# Lesson 05 — Separate login attempts

## Teaching intent

Show one client-side race: a later login replaces an earlier login's verifier in a shared variable, so callback A retrieves the wrong proof. The rejection is correct. The client must change its storage design and initiate fresh login when the original verifier is unavailable. This is a planned finite 46-second film, with timing adjustable after phone-size review; the existing lesson's 28 seconds is not a constraint.

The visual argument is ownership → overwrite → wrong lookup → rejection → explicit repair → fresh, isolated transactions. All values are abstract placeholders: `code A`, `verifier A`, `challenge A`, and equivalent B/C/D labels. They are never sample secrets, hashes, URLs, logs, or usable credentials. A verifier is the attempt's private proof; a challenge is its derived comparison value. Introduce that relationship through a small S256 transform before relying on it. Browser consent and other OAuth checks are outside this focused view.

## Correctness limits and evidence

RFC 7636 §§4.2, 4.4–4.6 specifies challenge derivation, association with the issued code, and comparison at exchange. A mismatched challenge returns invalid_grant; a match continues ordinary OAuth processing. Verified against [RFC 7636](https://www.rfc-editor.org/rfc/rfc7636#section-4.6), retrieved 2026-11-04. This supports the server comparison shown here.

The race and repair are the lesson's engineering scenario, informed by `video/oauth-pkce/sequence/lessons.json` item 5 and `content/concepts/oauth-pkce.json`. Per-transaction storage must include validated callback correlation and binding to the initiating client/browser session; an unchecked callback identifier is insufficient. The simple C/D table illustrates isolation, not a complete secure implementation. Preserve S256 and PKCE throughout. Never resurrect verifier A, retry the rejected pair, exchange code B, or imply an edit repairs an already failed transaction. The example deliberately starts new attempts C/D after the client fix.
