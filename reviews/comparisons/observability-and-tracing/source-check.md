# Guide relevance and primary-source verification

Retrieved 2026-10-19 during the comparative review. These checks used the primary pages themselves, not author claims or search summaries. The chapter's source objects now carry retrieval dates.

**Verdict: keep / core.** Once a team delegates multiple model/tool operations, locating the operation that consumed time and identifying missing telemetry relationships changes a real debugging decision. Starting with a deterministic harness, one instrumented transport and approved metadata is a manageable early practice. A fully managed observability platform is not a prerequisite; teams using only an opaque assistant without instrumentation access can treat the implementation exercise as later reference work.

The guide defines trace/span/context before using them, gives a concrete 0.6s + 2.4s synchronous example, preserves the fact that observability does not make it faster, and assigns the human responsibility for field selection and independent evaluation. Its prerequisite of tool design is reasonable. The exercise has observable criteria: correct parent relationship with distinct span IDs, teammate identification of the slow tool, and absence of a seeded fake secret. Those are bounded checks, not proof of exhaustive secrecy or correct generated code.

| Primary source inspected | Finding and boundary |
|---|---|
| [OpenTelemetry traces](https://opentelemetry.io/docs/concepts/signals/traces/) | A span describes an operation and includes parent information, timing and context. Trace ID groups spans; span ID identifies an individual span. Supports the overview and concrete parent inspection. A parent interval includes its nested operations; adding them again double-counts time. |
| [OpenTelemetry context propagation](https://opentelemetry.io/docs/concepts/context-propagation/) | Context is carried between processes; the receiving service creates a span in the same trace using the upstream span as parent. The guide correctly locates this in instrumentation/transport, not model memory. |
| [W3C Trace Context](https://www.w3.org/TR/trace-context/) | `traceparent` contains version, trace ID, parent ID and flags. Version 00 IDs use 32 and 16 hexadecimal characters; the videos' shorthand is illustrative. Outgoing operations update the parent ID; setting a sampled flag does not guarantee recording. Cross-vendor propagation is supported, so identical backend storage is not required by the protocol. |
| [GenAI client spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-spans.md) | The document is marked Development and includes model and execute-tool operations. It says sensitive instructions, inputs and outputs should not be captured by default. The guide's version warning and metadata-first policy are supported. |
| [GenAI agent/framework spans](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-agent-spans.md) | The document is marked Development; invoke-agent and execute-tool operations exist. Fable's labels use these operation concepts but combine task/status display fields; they should not be read as exact mandatory exported span names. Added that boundary to its metadata. |
| [Handling sensitive data](https://opentelemetry.io/docs/security/handling-sensitive-data/) | Data minimization means collect only telemetry needed for the purpose, avoid unnecessary personal information, and review captured fields. The guide's secret-omission test is useful but does not prove absence of every sensitive value. |
| [Sampling](https://opentelemetry.io/docs/concepts/sampling/) | Sampling selects a subset; head decisions cannot use the full outcome, and tail policies use more completed-span evidence. Missing evidence cannot prove no execution. With consistent whole-trace sampling a sampled trace need not be partially missing; the guide does not incorrectly claim all sampling causes partial trees. |

Engineering judgments, rather than direct standard mandates: begin at task/model/tool boundaries; make this core for delegated multi-operation work; inspect the long operation before blaming a dependency; use deterministic fixtures; define access/retention before richer collection. These remain explicitly framed as library practice. Neither HTTP success nor a successful span validates the generated answer; trace context is not an authorization credential. A long tool span can include waiting, transport, retries or process overhead, so the guide correctly requires investigation inside it before declaring the test process slow.

No implementation was exercised against a real OpenTelemetry backend in this review. These are primary-document checks of the guide and illustrative media, not a claim that the exercise was executed.
