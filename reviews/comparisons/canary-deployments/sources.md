# Primary-source verification

Retrieved and read on 2026-10-19. These are paraphrases; the numerical scenarios and editorial placement are the library's judgement, not source quotations.

- [Google SRE Workbook: Canarying Releases](https://sre.google/workbook/canarying-releases/) — checked the definition, evaluation integration, population/duration, monitoring breakdowns, attribution, shared failure domains, and noninteractive-work sections. Supports limited exposure plus an actual decision, per-version signals, representative completed work, concurrent comparison, and absolute service-health measures. The chapter's export-operation split is a useful application of fine-grained breakdowns. The 10,000/1,000/100 request counts and five-percentage-point gate are authored examples. The source does not justify a universal exposure share or confidence from a few animated packets.
- [Argo Rollouts: Analysis](https://argo-rollouts.readthedocs.io/en/stable/features/analysis/) — checked Custom Resource Definitions, Background Analysis and Inline Analysis, plus missing-result handling. Successful, failed and inconclusive analyses can continue, abort and pause a rollout; failed background analysis returns candidate weight to zero in the documented example. Empty results require a configured policy: they are not automatically safe, and the guide's pause-on-missing rule is a deliberate exercise policy.
- [Argo Rollouts: Canary Deployment Strategy](https://argo-rollouts.readthedocs.io/en/stable/features/canary/) — checked Overview and Pause Duration. Timed pauses wait; they do not evaluate health. Replica allocation approximates a configured percentage without traffic management. This supports the guide's request to measure actual routing.
- [AWS: Ensuring rollback safety during deployments](https://aws.amazon.com/builders-library/ensuring-rollback-safety-during-deployments/) — followed its redirect to AWS Builder Center and read protocol changes and two-phase deployments. New writes can make older readers incompatible; prepare/activate sequencing makes supported rollback paths explicit. Returning traffic to an older release is therefore not a claim that old data or completed side effects have been repaired.
- [Anthropic: Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) — checked outcome definitions, coding-agent graders and production-evaluation distinctions. Executable checks can inspect generated code and final environment state. This supports Sol's task-outcome check; the particular prompt rollout, HTTP response, traffic share and required-test failure are authored illustrations. Passing tests alone does not establish complete correctness.

## Guide verdict

Keep as **reference**. This chapter changes a concrete release-owner decision once agent-assisted code or a shared agent tool reaches production. It does not need to precede ordinary local model-assisted coding. The existing routing, tracing and eval prerequisites, human-owned thresholds, local exercise and observable abort outcome fit that supporting role. It should neither be deferred nor promoted to core merely because the example mentions agents.

The fixture is internally consistent: v1 exports 900, v1 other requests 8,100, v2 exports 100, v2 other requests 900; errors are respectively 0, 0, 40, 0. Thus pooled errors are 0.4%, all-candidate errors are 4%, and candidate export errors are 40%. The film and guide deliberately compare the last value to 0/900 control exports. Missing candidate samples or a missing control denominator cannot yield a valid pass; the guide now makes the control case explicit. Evaluation windows, statistical power, sticky session assignment, flakiness, delayed effects and rollback compatibility remain system-specific work.

## Fresh GPT-6.1 Sol verification, 2026-10-19

The first blind findings were saved before this section was read or appended. I reopened all five primary documents above using the web tool, rather than adopting the interrupted review's source-check claims. Concise findings:

- [Google SRE Workbook](https://sre.google/workbook/canarying-releases/): checked evaluation, representative size/duration, attribution, monitoring breakdowns, shared failure domains and noninteractive work. Supports the guide's concurrent comparison and operation breakdown. Shared dependencies can harm both populations; an absolute health check still matters. Long work units need time to finish, and mixing version pools within one unit contaminates the signal. The fixture and cohort percentages are editorial illustrations.
- [Argo analysis](https://argo-rollouts.readthedocs.io/en/stable/features/analysis/): checked analysis definitions/background behavior, inconclusive runs and empty results. Successful/failed/inconclusive analysis supports continue/abort/pause. Missing-data behavior depends on configured conditions; the exercise's pause policy is not an Argo default.
- [Argo canary strategy](https://argo-rollouts.readthedocs.io/en/stable/features/canary/): checked overview and pause duration. Replica allocation is a best-effort approximation without traffic management; a pause is a wait, not an evidence test.
- [AWS rollback safety](https://aws.amazon.com/builders-library/ensuring-rollback-safety-during-deployments/), redirected to Builder Center: checked distributed reader/writer compatibility, protocol changes and prepare/activate deployment. New data formats can prevent old versions from reading persisted state. Returning traffic alone does not repair previously written data or completed actions.
- [Anthropic agent evals](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents): checked grader types and coding-agent evaluation. Executable checks can assess resulting code separately from an API response; additional quality checks remain relevant. Sol's prompt deployment and strict failure gate are authored applications, not an implementation verified against an actual rollout controller.

Independent judgement: **keep / reference**, for the reasons already stated in the guide and in the final comparison. The chapter usefully moves an experienced team from “the endpoint is healthy” to evidence tied to a frozen artifact and a release-owner policy. It is needed when deploying live services or shared agent tooling; ordinary local AI-assisted coding can start without it. Existing limitations cover insufficient data, permissions, contamination and irreversible effects. No guide rewrite was needed in this fresh pass.
