# Content and source audit

Retrieved and read on 2026-10-19 after saving the blind findings. The following are primary documents actually opened during this review; this is not an endorsement of every current product claim on those pages.

- [Anthropic — Building effective agents](https://www.anthropic.com/engineering/building-effective-agents): its definitions distinguish predefined workflows from dynamically directed agents. The chaining, routing, parallelization, orchestrator-workers and evaluator-optimizer sections support the guide's taxonomy. Dynamic decomposition is different from a fixed fan-out. Simpler solutions and measured benefits precede added complexity. The article now notes that tooling has changed since its original publication; this chapter relies on the pattern definitions, not old framework recommendations.
- [GitHub — Using jobs in a workflow](https://docs.github.com/en/actions/how-tos/write-workflows/choose-what-workflows-do/use-jobs): `needs` normally requires prerequisite success; failure or skip propagates unless a conditional overrides it. The documented `always()` example is an explicit exception. The guide now states that exception, rather than inviting an unconditional interpretation.
- [GitHub — Use GITHUB_TOKEN for authentication](https://docs.github.com/en/actions/tutorials/authenticate-with-github_token): `permissions` can limit a workflow or job's token access. That concerns GitHub API authority, not a filesystem sandbox. The guide now separates these two boundaries explicitly.

Keep as **core**, after tool-design and agent-evals. An experienced team needs result contracts, dependency ordering, snapshot identity and explicit acceptance as soon as it delegates multiple checks. This guide turns those decisions into an observable fault-injection exercise instead of a catalogue of agent names. Routing and dynamic planning remain reference-level options within the overview, not prerequisites for adopting parallel review.

The following are editorial/engineering choices, not externally established performance results: freeze a review snapshot; use bounded read-only reviewers; preserve evidence and disagreements; invalidate both checks for the exercise after a repair; cap retries and stop incomplete on timeout; retain human approval; compare missed defects, false alarms and total human/model effort against one agent. The guide already labels conservative invalidation as an instructional choice. The exercise's success criteria are observable and appropriately include missing/stale/blocking results, retained evidence and a measured keep-or-simplify decision.

No real workflow implementation or model benchmark was executed. The media demonstrate selected mechanisms, not automated proof that these acceptance criteria have been implemented. The animations omit result-schema parsing, timeout/retry execution, contradiction resolution, access-control configuration and actual human examination of evidence. The fixed workflow may contain model/tool loops inside each worker; calling a node an agent does not make the coordinator dynamically planned.
