# Primary-source and guide review — 2026-10-19

Opened and read the relevant sections of all four primary documents on 2026-10-19, after saving before.md. These are document checks, not an executed agent evaluation.

- [Anthropic, Writing effective tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents): task-oriented tools, meaningful response fields, pagination/filtering/truncation, and evaluation support the guide's engineering recommendations. This is practitioner guidance, not a guarantee that any schema or naming convention improves every agent. Retaining follow-up IDs is a deliberate application judgment.
- [MCP tools, pinned 2025-11-25 specification](https://modelcontextprotocol.io/specification/2025-11-25/server/tools): checked structuredContent/outputSchema, error handling and security. Execution errors belong in tool results with isError; malformed protocol requests have a separate JSON-RPC failure path. Schemas do not enforce access; servers must validate inputs and implement access controls. The guide's status/items/code/cursor fields are explicitly illustrative, not mandatory MCP result fields. tools/list pagination is distinct from an application search's result pagination. Added the boundary that a transport timeout may yield no result for a server to mark isError.
- [JSON Schema object reference](https://json-schema.org/understanding-json-schema/reference/object): properties do not require presence; additional keys are allowed by default. required/additionalProperties support the guide's validation distinction. Schema validity alone proves neither completeness nor truth.
- [AWS, Timeouts, retries, and backoff with jitter](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/): checked failure, retry, side-effect, backoff and jitter sections (the URL redirects to AWS Builder Center). Retry traffic can amplify overload; a timeout does not imply a write had no effect. One delayed read retry is the library's exercise policy, not AWS's universal rule.

Keep **core**. The audience already knows API mechanics, but must now design what a model can infer from failure, absence and partial evidence. The four-fixture exercise produces observable outcomes: actual IDs, qualified conclusions, call-budget compliance, and rejection before backend execution. No prerequisite course is required for experienced software engineers; ordinary API and authorization knowledge is assumed. Production agents still need policy enforcement and evaluations. The guide's partial-coverage and authorization cases are useful precisely because the short videos omit them.

Added source retrieval dates and a narrow response-size boundary: limiting record count does not limit total tokens/bytes if records are unbounded. No curriculum promotion was performed; core is the reviewer judgment on the existing classification.
